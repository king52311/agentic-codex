# 集成自测脚本方法

## 适用场景

当业务链路依赖 MQ、数据库、定时任务、第三方接口或多个服务协同时，可以提供集成自测脚本用于快速验证。

适合覆盖：

- MQ 消息生产与消费。
- 定时任务触发与结果落库。
- 实时表到历史表的迁移。
- 外部接口回调与状态更新。
- 缓存、规则、告警、通知等跨模块链路。

## 脚本设计原则

- 尽量贴近真实业务入口，不只调用内部方法。
- 支持通过环境变量覆盖连接信息和业务参数。
- 提供测试环境默认值，但敏感信息不写入公共仓库。
- 输出关键步骤、耗时、查询结果和断言结果。
- 失败时给出明确错误原因，便于继续排查。

## 常用结构

脚本通常包含：

- 环境检查：确认 `curl`、`jq`、数据库客户端等依赖存在。
- 参数检查：确认必填业务参数存在。
- 数据准备：写入消息、调用接口或构造测试记录。
- 等待逻辑：给异步消费、定时任务、最终一致性留出时间。
- 结果查询：读取数据库、接口或日志中的最终状态。
- 简单断言：按预期判断应该存在实时数据、历史数据或无数据。

## 环境变量建议

基础连接：

- `API_BASE`
- `RABBITMQ_API_BASE`
- `RABBITMQ_USER`
- `RABBITMQ_PASS`
- `RABBITMQ_VHOST`
- `RABBITMQ_QUEUE`
- `PGHOST`
- `PGPORT`
- `PGDATABASE`
- `PGUSER`
- `PGPASSWORD`

业务参数：

- `TENANT_ID`
- `STATION_ID`
- `MODEL_ID`
- `DEVICE_ID`
- `CT_CODE`
- `SAMPLE_VALUES`
- `RECOVER_VALUES`
- `LOOKBACK_MINUTES`
- `WAIT_SECONDS`
- `EXPECT_RESULT`
- `EXTRA_JSON`

## 断言模式

建议提供少量稳定模式：

- `realtime`：预期实时数据存在。
- `history`：预期历史数据存在。
- `none`：预期不产生业务结果。

脚本不必替代完整自动化测试，但要能帮助开发者快速回答：

- 消息是否进来了。
- 任务是否跑了。
- 数据是否落到预期表。
- 恢复或关闭链路是否生效。

## 使用说明文档

每个自测脚本都应配套说明：

- 脚本目标。
- 依赖条件。
- 默认环境。
- 必填变量。
- 可选变量。
- 标准触发用例。
- 标准恢复或回滚用例。
- 已知限制和剩余人工检查项。
