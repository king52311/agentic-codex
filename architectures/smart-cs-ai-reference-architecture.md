# Smart CS AI 参考架构方案

配套流程图：`smart-cs-ai-framework-flow.svg`

## 适用场景

适合企业内部工具平台、智能客服平台、流程数据看板、知识库助手、OA/企微/钉钉集成类系统。

## 功能特点

- 单体仓管理前端、后端和边缘服务，适合中小团队快速迭代。
- 后端使用 FastAPI 分层：api、schemas、models、services、core、db。
- 前端使用 React + TypeScript，按页面、组件、接口、类型和状态拆分。
- 统一 RBAC 权限，工作台卡片、管理后台、接口访问都走权限控制。
- 外部系统数据先同步入本地库，再提供查询、筛选、统计、导出和看板。
- 定时任务负责 OA、企微、钉钉、知识库等数据同步。
- 文件类业务统一保留原始模板，导入解析入库，导出时基于模板回填。
- AI 对话、知识库、本地 ASR 作为独立能力模块接入业务页面。

## 推荐目录结构

```text
backend/
  app/
    api/          # 路由注册与接口实现
    core/         # 配置、安全、调度器
    db/           # 数据库会话与依赖
    models/       # SQLAlchemy 模型
    schemas/      # Pydantic Schema
    services/     # 业务逻辑和外部服务
  migrations/     # Alembic 迁移
frontend/
  src/
    api/          # 请求封装
    components/   # 公共组件
    pages/        # 业务页面
    store/        # 全局状态
    types/        # 类型定义
edge_compute/     # 独立边缘能力，如 ASR
doc/              # 数据库字典、前端规范、业务说明
data/             # 模板、上传、导出等数据文件
```

## 推荐业务模块形态

一个新业务模块优先包含：

- 后端模型：业务主表、明细表、同步日志或任务表。
- 后端 Schema：列表项、详情、筛选条件、保存请求、统计返回。
- 后端 Service：同步、统计、导入导出、外部系统适配。
- 后端 API：列表、详情、选项、保存、导入、导出、同步触发。
- 前端 API 封装：集中定义请求参数和响应类型。
- 前端页面：列表、筛选、详情/编辑、管理后台、看板。
- 权限配置：菜单入口、工作台卡片、接口权限和管理员能力。
- 文档记录：数据库字典、当前上下文、项目历史。

## 数据同步方案

- 外部系统数据不要直接驱动页面，先同步到本地专表。
- 同步表保留外部 request_id、workflow_id、user_id、原始状态和关键时间。
- 业务查询统一基于本地表，避免页面受外部系统波动影响。
- 同步任务要支持增量回填历史状态，避免只同步新增数据导致旧单据状态不更新。
- 异常数据修复应提供脚本，默认 dry-run，执行时记录影响范围。

## 权限方案

- 普通用户按本人、本人部门或业务归属过滤数据。
- 管理员通过权限点或角色查看全量和管理后台。
- 前端只控制入口展示，后端接口必须再次校验权限。
- 公开页面要单独隔离接口前缀和能力范围。

## 文件导入导出方案

- Excel 台账类业务保留原始模板。
- 导入时解析模板并落库，图片和附件进入独立上传目录。
- 导出时优先复用模板样式，按数据库最新数据覆盖单元格。
- 大文件、含图片导出优先改为后台任务，页面轮询任务状态。

## 前端交互方案

- 列表页统一提供筛选、分页、重置、导出。
- 下拉筛选优先支持可输入、可清空、可展开收起。
- 日期筛选复用公共日期组件。
- 超宽表格复用固定底部横向滚动条。
- 看板页展示总览指标、排行、最近记录和目标完成率。

## 验证方案

- 后端改动：运行相关文件 `py_compile`，涉及迁移时检查 `alembic heads` 和 `alembic upgrade head`。
- 前端改动：运行项目封装构建脚本。
- 接口联动：检查前后端字段、筛选口径、分页参数和权限条件。
- 数据修复：记录 SQL 或脚本参数、影响行数和复查结果。
