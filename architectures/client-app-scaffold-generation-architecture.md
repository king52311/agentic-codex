# 客户端应用生成框架参考架构

## 适用场景

用于快速搭建企业内部的独立桌面客户端应用，典型技术栈为 React + TypeScript + Tailwind CSS + Electron，开发态支持 Web 热更新，打包态输出桌面安装包或目录包。

## 目标

把“新应用从 0 到可交付”拆成稳定流水线：

1. 先确定应用名、英文目录、版本号和业务边界。
2. 再生成标准目录、脚本、文档和基础壳子。
3. 再接入公共组件库、数据库、文件处理、导入导出、更新和打包能力。
4. 最后只补业务差异逻辑，不重复造框架层轮子。

## 核心约束

- 每个应用必须有独立英文目录。
- 首次版本统一为 `1.0.0`。
- 展示名使用当前组织或项目约定的统一前缀；没有约定时使用清晰的业务中文名称。
- 每个应用都要有自己的 `start.sh`、`build.sh`、`.nvmrc`。
- 每个应用都要有 `docs/REQUIREMENTS.md`、`docs/PLAN.md`、`docs/DATABASE.md`、`docs/USAGE.md`、`docs/ARCHITECTURE.md`。
- 应用内必须有“帮助”入口，直接展示使用说明文档。
- 开发默认支持 Web 热更新；桌面模式用于壳层联调和打包验证。
- 公共能力放到 `packages/client-common`，应用只保留业务差异。
- 脚本参数要短、无符号、≤ 8 字符。

## 推荐生成流程

### 1. 输入约定

先收集这些信息：

- 应用中文名称
- 英文目录名
- app_code
- platform
- 内部版本号
- 是否需要数据库
- 是否需要 Excel / 文件导入导出
- 是否需要更新检查
- 是否需要桌面壳
- 是否需要 Web 调试

### 2. 生成目录

优先生成：

```text
apps/<english-name>/
  src/
  electron/
  shared/
  docs/
  build/
  resources/
  scripts/
  start.sh
  build.sh
  .nvmrc
  app.config.json
```

### 3. 生成文档

每个应用必须先生成文档骨架，再写业务代码：

- 需求：应用做什么
- 计划：先做什么、后做什么
- 数据库：表结构、字段、索引、备份方式
- 使用说明：启动、导入、筛选、导出、更新
- 架构：页面、数据流、IPC、公共组件依赖

### 4. 生成公共接入层

优先补这些基础能力：

- 统一 UI 组件
- 文件选择 / 读取 / 保存
- 数据库连接与备份
- Excel 模板读取与回写
- 更新检查与下载安装包处理
- Web 调试 API
- 统一错误提示和 toast

### 5. 生成业务骨架

建议顺序：

1. 列表和筛选页
2. 新建 / 编辑弹窗
3. 导入 / 导出
4. 统计看板
5. 归档 / 激活 / 删除
6. 更新 / 帮助 / 备份

### 6. 生成逻辑代码

生成逻辑时优先按下列层次写：

- `shared/contracts.ts`：类型和协议
- `electron/main.ts`：桌面 IPC、文件、数据库、更新
- `electron/preload.ts`：安全桥接
- `src/lib/api.ts`：Web 调试 API 兜底
- `src/App.tsx`：页面与交互
- `electron/services/*`：数据库、Excel、导入导出

## 关键实现点

### 目录和脚本

- 根目录脚本提供短参数入口。
- 每个应用脚本同时支持开发和构建。
- Web 模式默认热更新，桌面模式用于壳层联调。

### 数据

- 数据先落本地数据库，不直接依赖外部来源。
- 导入、编辑、同步、归档、删除都要有状态约束。
- 数据库文件存放在系统应用数据目录，避免污染源码和 Git。

### 文件与 Excel

- 保留原始模板。
- 导入前先校验模板结构。
- 回写只改应用约定单元格。
- 导出要按当前筛选条件生成。

### 更新

- 只在本地版本号小于接口返回内部版本号时才弹更新。
- 更新前先备份数据库。
- 强制更新只允许继续，不允许随手关闭。

### Web 调试

- Web 调试模式要能完整覆盖导入、编辑、同步、导出。
- API 未启动时要给出明确提示。
- 前端和桌面模式共用业务逻辑，避免两套实现漂移。

## 一次性落地清单

新项目生成后，最少检查这些项：

- 应用目录、版本号、脚本、文档齐全
- 公共组件接入正常
- 主页能展示列表和筛选
- 导入、导出、更新、备份可跑通
- Web 热更新可用
- 桌面打包可用
- 错误提示清晰，空数据可用

## 输出给下游 Agent 的提示词模板

可以直接按这个方式发起新项目生成：

> 请基于客户端应用生成框架，创建一个名为「XXX」的独立应用，英文目录为 `xxx`，首次版本 `1.0.0`。请先生成应用目录、脚本、文档、公共组件接入、数据库与 Excel 逻辑，再补业务页面和导入导出能力；开发态默认支持 Web 热更新，桌面态支持 Electron 打包。
