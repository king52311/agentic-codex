# 客户端应用创建通用规范

## 应用目录

- 每个客户端应用必须有独立英文目录。
- 目录名使用小写英文、数字和短横线。
- 不同应用不得混放源码、文档、资源和构建脚本。

## 版本与命名

- 新应用首次创建版本号统一为 `1.0.0`。
- 应用展示名称应使用当前组织或项目约定的统一前缀；没有约定时使用清晰的业务中文名称。
- 包名和目录名保持英文，展示名称使用中文业务名。
- 应用顶部标题区默认不展示英文副标题；除非用户明确要求，不在首页标题上方添加英文名称。

## 文档

每个应用目录必须包含应用自己的文档，至少包括：

- `docs/REQUIREMENTS.md`：需求文档。
- `docs/PLAN.md`：计划文档。
- `docs/DATABASE.md`：数据库说明文档；无数据库时说明“不使用数据库”。
- `docs/USAGE.md`：应用使用说明文档。
- `docs/ARCHITECTURE.md`：应用架构说明。

应用内必须提供“帮助”入口，点击后展示 `docs/USAGE.md` 对应的使用说明。

## 脚本

- 每个应用目录必须有 `start.sh`、`build.sh`、`.nvmrc`。
- 开发调试默认支持 Web 热更新模式。
- 如有桌面壳，额外支持桌面调试模式。
- 脚本参数必须简洁，不带符号，长度控制在 8 个字符以内。
- 根项目聚合脚本应为每个应用提供短参数入口。

## Windows 安装、覆盖安装与卸载

适用场景：Electron Windows 客户端使用 NSIS 安装包，应用会启动 Worker、转换器、媒体处理器、数据库服务等外部子进程，并支持覆盖安装或卸载。

- 安装器的运行检测只能匹配主程序和明确登记的外部子进程；禁止用“可执行文件路径位于安装目录”作为唯一条件，否则安装器从安装目录启动时会把自身误判为正在运行的应用。
- 关闭应用时必须同时结束 Worker 及其启动的外部进程。启动外部进程后应记录 PID；正常完成、超时、取消、窗口关闭和异常退出时都要清理进程树。
- Windows 外部进程清理优先使用 `taskkill /PID <pid> /T /F`；安装或卸载前可按已知进程名补充兜底清理，但不得无范围终止无关程序。
- NSIS 自定义 `customCheckAppRunning` 时，只处理 `${APP_EXECUTABLE_FILENAME}` 和应用明确内置的进程名，不能沿用会匹配安装器自身的宽泛目录扫描。
- 覆盖安装验证必须包含：主窗口关闭、后台解析中关闭、外部进程异常残留、安装器位于安装目录、重复安装、卸载六个场景。
- 构建完成后必须区分验证安装器、卸载器和主程序启动；三者是独立问题，不能用安装包可解压代替 Windows 实机运行验证。

## 公共库

- 数据库连接、UI 公共组件、文件处理、文件读取、SQL 校验等跨应用能力，应放到框架公共组件库。
- 应用优先调用公共组件库，构建时由应用自身打包进最终产物。
- 应用内只保留业务特有逻辑，不重复沉淀通用能力。
