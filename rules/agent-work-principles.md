# Agent 通用工作原则

## 先理解，再修改

- 先阅读现有实现，再决定改动位置。
- 搜索相似页面、接口、模型、Schema、工具函数和样式约定。
- 不要一上来重写已有结构。
- 优先在现有模块边界内做小步改动。

## 保持项目风格

- 优先复用项目已有框架、组件、工具函数、异常格式和命名方式。
- 非必要不新增抽象层。
- 非必要不引入新依赖。
- 前后端同一概念保持命名一致。

## 架构边界

- 路由层负责请求、鉴权和响应组织。
- 业务逻辑优先放在 service 或项目已有业务层。
- 数据结构变更要同步检查模型、Schema、接口返回、前端类型和文档。
- 共享能力优先抽成公共组件、hook、工具函数或服务，不在业务页重复实现。

## 禁止行为

- 未确认现有实现前大面积重构。
- 未补迁移就只改数据库模型。
- 在前端硬编码后端返回结构的猜测字段。
- 绕过权限校验。
- 提交密钥、Token、账号密码。
- 为小改动引入重量级依赖。

## 结果说明

- 说明改了什么。
- 说明验证结果。
- 涉及配置、依赖、数据库、生产数据时说明影响范围。
