# Python 通用规范

## 基本原则

- 优先遵循项目现有 Python 版本、框架和目录分层。
- 优先写清晰直接的代码，不为小问题制造复杂抽象。
- 新增外部依赖前先确认标准库或现有依赖是否已能满足需求。
- 异步项目保持异步链路一致，避免在 async 路径中加入阻塞 I/O。

## 类型与结构

- 公共函数、服务层函数和复杂返回值应补类型标注。
- 数据入参和出参优先使用项目已有 Schema / DTO / Pydantic 模型。
- 路由层只处理请求、鉴权、响应组织；业务逻辑优先放到 service 层。
- 文件上传、外部调用、后台任务要有明确错误处理和日志。

## 错误处理

- 不吞异常；需要降级时写明降级条件。
- 面向 API 的错误返回要保持项目统一格式。
- 外部服务调用要考虑超时、重试、鉴权失败和响应结构变化。

## 验证

- 修改 Python 代码后，至少运行相关文件的 `py_compile` 或项目测试。
- 修改导入、依赖、配置加载时，必须做 import 级校验。
- 涉及数据库迁移时，检查迁移头和升级流程。
