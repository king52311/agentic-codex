# TypeScript / 前端通用规范

## 基本原则

- 优先复用项目已有组件库、布局模式、API 封装和状态管理方式。
- 不为局部页面引入新的 UI 体系或状态管理方案。
- 展示字段、接口参数、枚举值要与后端类型保持一致。
- 避免在页面里散落重复筛选、分页、弹窗、表格逻辑，已有公共组件时优先复用。

## 类型

- 禁止用 `any` 掩盖接口不确定性，除非项目已有约定或第三方类型确实不可控。
- API 响应、表单值、列表项、筛选参数应有明确类型。
- 后端字段调整后，同步检查前端类型、接口封装和使用点。

## UI

- 优先使用设计系统组件和语义化 token。
- 新增下拉框、日期选择、超宽表格时，先读取 `rules/frontend-common-components.md`。
- 表单控件要处理加载、空值、禁用、错误、清空等常见状态。
- 表格超宽时应使用项目通用横向滚动方案。
- 移动端和窄屏要检查文本换行、按钮拥挤和内容遮挡。

## 验证

- 修改前端代码后，按项目约定运行构建命令。
- 若项目有封装脚本，优先执行封装脚本，不绕过项目验证流程。
