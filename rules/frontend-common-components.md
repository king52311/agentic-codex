# 前端通用组件使用规范

## 基本原则

- 新增业务页面前，先查项目是否已有公共组件、业务组件、hook 和样式指南。
- 同类交互必须优先复用公共组件，不在业务页面里重复手写状态、事件和样式。
- 如果项目已有二次封装组件，优先使用二次封装，而不是直接拼基础 HTML。
- 新组件只有在确实可复用、能减少重复或符合项目组件体系时才抽取。

## 下拉筛选

新增筛选下拉框时，默认优先复用项目公共下拉筛选组件。

推荐能力：

- 可输入搜索。
- 可清空。
- 可展开和收起。
- 支持本地下拉筛选。
- 支持受控值和重置。
- 选项较多时不撑破布局。

除非用户明确要求原生 `select`，或项目已有组件约束不支持，否则不要在业务页里重复手写一套下拉逻辑。

## 日期选择

新增日期选择、日期筛选、月份选择时，默认优先复用项目公共日期组件。

推荐能力：

- 受控值。
- 可清空。
- 统一展示格式。
- 移动端可用。
- 与项目表单和筛选栏样式一致。

不要在多个业务页面里重复手写原生 `input[type=date]` 或重复造日期弹层。

## 表格横向滚动

业务表格列宽超过屏幕时，默认优先复用项目公共横向滚动组件或 hook。

推荐交互：

- 表格自身保持横向滚动。
- 当原生横向滚动条不在当前视口内时，页面底部显示固定横向滚动条。
- 当原生横向滚动条进入视口时，固定横向滚动条自动隐藏。
- 固定滚动条视觉上接近原生滚动条，不遮挡主要操作。
- 多个业务页面共享同一组件或 hook。

不要在业务页重复手写浮动滚动条，也不要只放普通 `overflow-x-auto` 后忽略首屏可操作性。

## 表格与筛选联动

- 筛选条件变化后，列表分页默认回到第一页。
- 顶部统计、导出、列表请求要确认筛选口径是否一致。
- 导出是否使用当前筛选条件，应按业务规则明确，不能靠前端猜测。
- 排序、分页、筛选参数要集中管理，避免多个状态源互相打架。

## 响应式与可用性

- 筛选栏在窄屏下要允许换行或横向滚动，避免按钮和输入框互相挤压。
- 按钮文字、表头文字、单元格内容不能遮挡或溢出得不可读。
- 加载、空数据、错误、禁用、无权限状态要完整处理。
