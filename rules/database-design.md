# 数据库设计与迁移通用规范

## 基本原则

- 模型、Schema、迁移、接口返回和前端类型要同步考虑。
- 新表、新字段、索引和约束要有清晰业务含义。
- 字段命名保持项目已有风格，避免同一概念出现多套命名。
- 时间字段、金额字段、状态字段要统一单位和语义。

## 迁移

- 修改表结构必须补迁移文件，不能只改模型。
- 新增表或关键字段后，同步更新项目数据库字典或说明文档。
- 迁移脚本要可重复理解，避免依赖本机临时数据。
- 修改字段、删除字段、删表、重命名表等高风险操作，执行前先确认。
- 新增和修改类迁移 SQL 经校验后直接执行；删除表、字段、数据或其他破坏性操作必须先询问用户，获得明确确认后再执行。

## 数据安全

- 生产数据修复应优先 dry-run 或先查询确认影响范围。
- 批量更新要有过滤条件、影响行数记录和回滚思路。
- 不提交密钥、账号、Token、真实敏感个人信息。
